# Security policy

## Reporting a vulnerability

Use [GitHub's private vulnerability reporting](https://github.com/ezequiel-gb/vextra/security/advisories/new) for security issues. Include the affected version, reproduction steps, expected impact and a minimal proof of concept where practical.

Do not include browser cookies, authentication tokens, private transcripts or other personal information. Keep exploitable details private while the report is assessed.

If the private-reporting form is temporarily unavailable, open an issue asking for a private reporting channel without describing the vulnerability or attaching sensitive material.

## Scope

The current 1.x release line is the focus for fixes. Relevant reports include unsafe URL/message handling, executable content in previews/templates, access beyond the declared YouTube scope, data disclosure and dependency vulnerabilities. Unavailable captions without a security impact are ordinary compatibility issues.
